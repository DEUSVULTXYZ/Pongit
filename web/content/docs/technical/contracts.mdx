## Bindings and upgrades

Game, market, vault and tournament links are sealed before use. These contracts have no upgradeable proxy. A new deployment may inherit ratings, but existing balances and financial rights remain attached to the old contracts.

The treasury is immutable where specified by the contract constructor. Replacing it requires a compatible new deployment, not an undocumented administrative edit to an existing match.

## Match references

`v4:12` means match 12 in V4. It is different from `v3:12`. Envio and private replay notes use deployment-qualified references. Active numeric API routes are scoped by `/api/config`; legacy reads require the chosen deployment parameter.

Code must preserve the deployment when storing a receipt, replay, position or payout origin. Never assume a number alone identifies a match across upgrades.

## Financial compatibility

V4 transfers due winnings and refunds to the fixed wallet recipient. V1–V3 claims credit their original vaults and need a signed withdrawal. A UI rollback must retain support for every deployment already accepted by the relayer journal.
