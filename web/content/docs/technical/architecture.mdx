## One authoritative game

PONGIT is a Next.js web application with Solidity contracts, a Node relayer and an Envio indexer. Production runs on a VPS behind Caddy HTTPS. PostgreSQL and internal services are private; the browser does not connect directly to the database.

The rooms path is browser → hosted Solidity engine → published Monad state. The financial path is browser owner signature → persistent relayer → Monad market/vault. These paths have different confirmation guarantees.

| Relayer | Validate signed requests, persist jobs, submit transactions and track receipts |

## Mera and Envio

[Mera](https://github.com/category-labs/mera) derives the wallet from PRF-capable passkeys. An independent namespace powers [the private notebook](/docs/account/notebook). The derived keys have different purposes; an arcade authorization never gains wallet spending rights.

[Envio](https://docs.envio.dev/docs/HyperIndex/overview) provides indexed records rather than replacing the contracts' authority. Payment candidates are checked onchain before submission. Removing a retained replay does not remove settlement records.

## Current transport and integrations

The live transport is **Monad Testnet, chain 10143**, using public RPC services through application gateways. The site does not currently route transactions through Alchemy, and does not represent a sponsor integration as active just because it was considered.

The main [rooms arcade](/docs/playing/rooms) uses a multi-match Interlude engine. Mera signs a scoped SDK grant and game calls go directly to the hosted operator. Classic and Chaos results and ratings are computed in the Solidity application and published to Monad. The original single-arena lab and V4 are separate deployments.

Chaos uses a testnet VPS attester to sign actual paid MON pressure at an exact between-rally cutoff. Its authority covers handicap input, not financial settlement. The Monad adapter accepts a terminal result only after hub status returns to None following closure and the challenge period. The rooms coordinator indexes its own market events and reconciles contracts; it does not claim the new rooms stream is already an Envio replay pipeline. Envio continues to index V1 to V4.

Scheduled renewal drains games, closes the delegation, waits the one-hour challenge period, finalizes results and verifies the hosted node's new epoch. This creates a maintenance interval and delayed payouts. No browser prediction or VPS signature bypasses that wait.

## Trust and limits

The browser may display a prediction that differs from later confirmation. The relayer can delay or fail to submit, and Envio can lag. Immutable contracts constrain accepted actions, but the service does not claim censorship-proof scheduling or an independent security audit. [Authentication boundaries](/docs/technical/permissions).
